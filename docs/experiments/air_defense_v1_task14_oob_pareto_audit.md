# AirDefense v1.0 OOB 安全-停止 Pareto 可行性审计

更新时间：2026-07-22  
实验状态：完成，主门控通过，等待独立确认

## 1. 研究问题

上一阶段的选中目标在零阈值下仅 `1/3` 个 OOB 种子可行，最终独立批次为 `0/3`，
且主要表现为过度交战。本实验检验：连续 score 是否仍存在同时满足安全交战和资源
停止约束的跨批次、跨场景决策边界。

## 2. 实验协议

- 输入：三训练批次的1737行 OOB 预测；
- 冻结主目标：`scenario_robust_reliable_cost`；
- 模型种子：20、21、22；
- 每个主目标种子：183个可靠组，68个 engage、115个 no-op；
- 阈值集合：所有唯一 score 相邻中点及边界；
- 新 rollout：0；
- 最终 test 访问：false；
- 主门控：至少2/3种子存在满足全部总体、批次、场景与安全符号约束的阈值。

输入文件 SHA-256 为
`cdd7b4cd644bcc281393da9b71e502b739018314220082aa5592f1d0804233ab`。

## 4. 消融与尺度诊断

诊断目标并非都可通过。`standard` 为2/3可行，`scenario_robust` 仅1/3可行，冻结的
`scenario_robust_reliable_cost` 为3/3可行。这支持保留上一阶段冻结目标，而不是事后
切换到更有利的目标函数。

共享原始阈值最多使2/3种子通过；最佳共享候选仍有最小种子约束余量 `-0.175`。
seed20/21 的可行区间靠近零，而 seed22 的区间位于 `0.3540-0.3629`。这说明 score
排序中存在可用信息，但随机种子间的尺度与偏置没有统一。

## 5. 结论

本阶段主门控通过。当前证据否定了“连续 score 完全不可分”的解释，并把问题收窄为
OOB 决策边界校准和跨种子尺度漂移。结果尚不构成独立泛化成功：seed22 只有两个可行
阈值，选定点最小余量为0，边界脆弱。

因此只放行一次全新独立确认批次。确认阶段必须冻结当前目标、阈值选择规则和全部门槛，
不得读取新批次后重新扫描 OOB 规则。只有至少2/3种子在新批次完整通过，才允许恢复
最小 MCH-PPO 实验；GNN仍不进入。
