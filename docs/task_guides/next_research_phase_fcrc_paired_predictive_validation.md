## 1. 任务目标

N2 已证明未来可覆盖性责任证书（FCRC）在冻结 R2 状态中非退化、可计算，且不能被单元成本或目标威胁权重简单替代。N3 不再检查“证书能否算出”，而检验一个可证伪的预测命题：

> 在同一状态、同一防御单元内，FCRC 更高的合法交战目标，相比 FCRC 更低的合法目标，是否会因占用当前资源而对其他威胁造成更大的因果损害？

N3 是一次冻结的离线反事实验证，不更新 Actor，不把 FCRC 写入 reward、loss 或 action mask，也不启动 10k、30k 或 100k 在线实验。

## 2. 冻结因果估计量

对上下文 \(c=(s,i)\) 中单元 \(i\) 的合法目标 \(j\)，定义：

- \(a_j\)：当前步固定单元 \(i\) 交战目标 \(j\)，其余单元按冻结策略和固定随机数采样；
- \(a_0\)：当前步固定单元 \(i\) 为 no-op，其余单元使用与 \(a_j\) 相同的随机数；
- 后续策略、命中随机带和环境随机性在两个分支间使用共同随机数；
- 评价时排除当前目标 \(j\)，只统计其他初始存活威胁。

其他威胁截获权重损失：

\[
H^{I}_{c,j}
=
I_{c,a_0}^{(-j)}
-
I_{c,a_j}^{(-j)}.
\]

其他威胁泄漏损伤增量：

\[
H^{D}_{c,j}
=
D_{c,a_j}^{(-j)}
-
D_{c,a_0}^{(-j)}.
\]

正值均表示交战 \(j\) 对其他威胁更有害。对同一上下文选取 FCRC 最高和最低的两个目标：

\[
\Delta H^{I}_{c}
=H^{I}_{c,j_{\mathrm{high}}}-H^{I}_{c,j_{\mathrm{low}}},
\quad
\Delta H^{D}_{c}
=H^{D}_{c,j_{\mathrm{high}}}-H^{D}_{c,j_{\mathrm{low}}}.
\]

主命题要求 \(\Delta H^{I}\) 为正；\(\Delta H^{D}\) 是安全一致性结局。

## 3. 样本和分支冻结

### 3.1 来源策略

- 场景：`medium`、`time_pressure`、`heterogeneity_pressure`；
- 冻结策略种子：17、18、19；
- 使用 R2 的冻结来源模型，不重新训练；
- Actor 参数变化必须为 0。

### 3.2 全新状态

- 状态采集基准种子：`1483000`；
- 分支随机数基准种子：`1493000`；
- 每个“场景 × 策略种子”先采集 12 个可审计上下文；
- 所选上下文的 observation hash 必须与 R2/N2 已用状态零重叠；
- N3 上下文 ID 添加 `n3_` 前缀，避免与旧批次同名。

### 3.3 选择规则

选择必须在观察任何反事实结局前完成：

1. 每个上下文计算同一单元所有合法目标的 FCRC；
2. 仅保留 FCRC 跨度大于 `1e-9` 的上下文；
3. 每个“场景 × 策略种子”按 FCRC 跨度降序、上下文 ID 升序选择最多 4 个；
4. 九个区组各至少 1 个，总计至少 24 个；
5. 每个上下文选择 FCRC 最大目标为 high、最小目标为 low；并列时按目标索引升序。

不得按 rollout 结果、回报、损伤或显著性重新选择上下文。

### 3.4 重复和预算

- 每个上下文执行 64 组共同随机数重复；
- 每组包含一个 no-op 分支、一个 high-FCRC 分支和一个 low-FCRC 分支；
- 最大新增环境 transition 数：400,000；
- 若超过预算，只能停止并判为完整性失败，不能减少样本后重算门槛。

## 4. 预冻结统计方法

### 4.1 主方向检验

- 上下文级主变量：\(\Delta H^{I}_{c}\)；
- 报告均值、标准误和 95% 区间；
- 使用固定种子、10,000 次符号翻转随机化的单侧检验；
- 报告候选目标级 FCRC 与平均 \(H^{I}_{c,j}\) 的 Spearman 相关。

### 4.2 增量预测检验

以候选目标级平均 \(H^{I}\) 为因变量，执行按“场景 × 策略种子”留一区组交叉验证：

- 基线特征：单元资源成本、目标威胁权重、当前命中概率、动作前可覆盖值、动作后可覆盖值、合法目标数；
- 完整特征：基线特征加 FCRC；
- 训练折内标准化，使用带截距的最小二乘；
- 主指标：完整模型相对基线模型的交叉验证 MAE 降幅。

### 4.3 禁止的事后分析

以下分析可作为附录探索，但不能改变 N3 判决：

- 看到结果后改变 high/low 选择；
- 调整 repeats、显著性阈值或特征集合；
- 删除“异常”场景、种子或上下文；
- 用 reward、总回报或当前目标结果替换冻结主结局；
- 追加新种子直到显著。

## 5. 冻结门槛

| 命题 | 通过条件 |
| --- | --- |
| N3-P1：独立性与完整性 | 新状态与 R2/N2 hash 零重叠；至少 24 个上下文；九区组各至少 1 个；选择发生在结局计算前；Actor 参数变化为 0 |
| N3-P2：因果方向 | 平均 \(\Delta H^{I}>0\)；单侧符号翻转 `p<0.05`；候选级 `Spearman(FCRC, H^I)>0.25` |
| N3-P3：增量预测价值 | 加入 FCRC 后留一区组 CV MAE 相对下降至少 5% |
| N3-P4：跨场景与安全一致性 | 三个场景中至少两个场景的平均 \(\Delta H^{I}>0\)，且总体平均 \(\Delta H^{D}\ge 0\) |
| N3-P5：执行完整性 | 恰好 64 次重复；新增 transition 不超过 400,000；全部原始分支和聚合产物可追溯；Actor 参数变化为 0 |

所有门槛在正式 rollout 前冻结。P2 或 P3 失败时，不得通过增加训练、调参或更换主结局挽救。

损害存在中等秩相关，但高低配对的平均方向不显著，且加入 FCRC 后没有
任何留一区组增量预测价值；损伤结局还呈相反方向。因此不能将静态证书升级
为策略约束、shield 或在线算法。

新状态下的不同单元上下文误判为 P1 失败。该条件不在预注册中。修正只重算
P1 和出口，不改变选择、rollout、统计量或任一阈值，也没有重跑分支；修正
记录保存在 `gate_correction.json`。
