## 1. 阶段背景

当前项目已经完成：

- `AirDefenseResourceAssignmentEnv v1.0` 集中式联合动作环境；
- 6 种规则基线（含 Hungarian 优化分配）；
- PPO 与 Maskable PPO；
- 100k 训练步、5 个随机种子的正式对比实验；
- 配对评估场景、学习曲线、95% 置信区间和完整实验留档。

已有实验支持以下结论：

```text
Maskable PPO 稳定优于普通 PPO，并消除了非法动作；
Maskable PPO 已达到 greedy_damage 强规则基线水平；
当前证据尚不能证明 Maskable PPO 稳定超过 greedy_damage。
```

因此，当前主要缺口不再是“能否训练强化学习算法”，而是：

1. 当前默认场景是否足以区分不同决策方法的能力；
2. 强化学习相对优化分配方法的价值出现在哪类条件下；
3. 平坦 MLP 状态表示是否成为进一步提升的瓶颈；
4. 后续图结构算法应解决什么可以被实验验证的问题。

## 2. 阶段总目标

建立一套可解释、可复现的场景压力测试体系，引入强非学习基线，定位现有策略的失效条件，并据此决定是否进入约束感知图强化学习研究。

本阶段最终应回答：

```text
在什么场景压力下，greedy_damage、Hungarian 分配和
MLP Maskable PPO 出现稳定且可解释的性能差异？
```

## 6. 任务二：建立场景难度与压力配置

### 6.1 设计原则

第一轮场景分层保持结构维度固定：

```text
保护区域数 = 2
防御单元数 = 3
目标数 = 5
```

原因是当前环境的观测和动作维度随目标数量变化。现有 MLP/SB3 模型不能直接训练 5 目标后测试 8 目标。跨目标数量泛化应在 padding、target mask 或图观测完成后研究。

### 6.2 工作内容

建立以下命名配置：

| 配置 | 目的 | 推荐调节方向 |
| --- | --- | --- |
| `easy` | 验证策略能否学会基本任务 | 到达时间更长、规避更低、资源更充足 |
| `medium` | 保留当前正式基准 | 使用当前默认参数 |
| `hard` | 制造联合分配和资源保留压力 | 到达时间更短、规避更高、资源更紧张 |

除组合难度外，还应建立单因素压力配置：

- `time_pressure`：只改变出生距离、目标速度或到达时间；
- `resource_pressure`：只改变弹药、冷却或资源成本；
- `intercept_uncertainty`：只改变命中概率或目标规避；
- `damage_pressure`：只改变载荷、威胁或区域价值；
- `heterogeneity_pressure`：扩大不同资源射程、成本和命中率差异。

难度配置应采用命名工厂或注册表管理，例如：

```text
get_air_defense_v1_scenario("easy")
get_air_defense_v1_scenario("medium")
get_air_defense_v1_scenario("hard")
```

### 6.3 交付物

- 场景配置模块或场景注册表；
- `easy/medium/hard` 三个组合配置；
- 至少 4 个单因素压力配置；
- 场景参数表和设计说明；
- 场景确定性、合法性和维度测试。

### 6.4 验收标准

- 每个场景均可独立创建、重置、运行至终局并关闭；
- 所有场景保持相同的观测维度和动作维度；
- 相同场景名与相同随机种子生成相同初始状态；
- 不同场景的完整参数进入 `experiment_config.json`；
- 使用共同评估种子运行至少 500 个配对回合后，`easy` 与 `hard` 在平均奖励和平均损伤上形成方向一致的难度差异；
- `hard - easy` 的配对平均损伤差异 95% CI 不跨 0；
- 单因素配置每次只改变预先声明的一类压力变量；
- 如果难度排序不成立，应先重新校准场景，不进入算法创新阶段。

## 7. 任务三：实现 Hungarian 优化分配基线

### 7.1 工作内容

根据每个时间步的合法资源目标关系构造收益矩阵：

```text
score(unit_i, target_j)
= 期望避免损伤
+ 期望拦截收益
- 资源成本
```

基线应满足：

- 每个防御单元最多选择一个目标；
- 每个目标最多分配一个防御单元；
- 不可行动作不能进入匹配；
- 通过虚拟目标列支持 no-op；
- 允许收益不为正时保留资源；
- 相同状态下输出确定性动作。

Hungarian 基线只解决当前时间步的一对一最优匹配。若后续需要允许多个资源协同攻击同一目标，应新增 MILP 或有限时域优化基线，而不是让 Hungarian 承担该语义。

### 7.2 交付物

- `HungarianDamageReductionPolicy` 或等价实现；
- 小规模收益矩阵单元测试；
- 与穷举最优结果的正确性对比；
- 统一 baseline 注册与命令行支持；
- 决策耗时记录。

### 7.3 验收标准

- 策略在全部测试回合中非法动作数为 0；
- 每个资源和目标满足一对一匹配约束；
- 对小规模固定状态，Hungarian 结果与穷举最大收益一致；
- 对同一状态重复调用返回相同动作；
- 在相同瞬时收益函数下，Hungarian 的单步目标值不低于 `greedy_damage`；
- 端到端评估可以输出与其他方法相同格式的全部指标；
- 决策耗时被记录，但不要求其最终回合奖励一定高于强化学习。

## 8. 任务四：补充诊断性评价指标

### 8.1 工作内容

在现有指标基础上新增：

| 指标 | 含义 |
| --- | --- |
| `high_threat_leak_rate` | 高威胁目标突防率 |
| `zone_weighted_damage` | 按区域价值加权的损伤 |
| `assignment_conflict_rate` | 多资源冲突分配比例 |
| `overkill_rate` | 过度分配发生比例 |
| `damage_reduction_per_ammo` | 单位弹药带来的损伤降低 |
| `resource_cost` | 累计资源使用成本 |
| `decision_time_ms` | 单步决策耗时 |

需要先给出“高威胁”“冲突”和“过度分配”的明确计算定义，不能只增加字段名。

### 8.2 交付物

- 每回合原始指标；
- 跨回合、跨种子汇总指标；
- 均值、标准差和 95% CI；
- 指标定义文档与测试；
- 旧实验结果字段的兼容处理。

### 8.3 验收标准

- 每个指标有唯一、可执行的数学或程序定义；
- 原始回合数据可以重新聚合得到汇总表；
- 旧指标名称和含义不发生静默变化；
- 所有比例指标位于合法范围；
- 决策耗时不计入环境状态转移时间时，应在文档中明确说明；
- 固定测试场景可以人工验证冲突、过度分配和加权损伤结果。

## 9. 任务五：升级统一实验与泛化评估

### 9.1 工作内容

统一实验入口应支持：

```text
--train-scenario medium
--eval-scenarios easy medium hard
--methods greedy_damage hungarian_damage maskable_ppo
```

实验需要区分：

- 训练场景；
- 测试场景；
- 训练随机种子；
- 配对评估场景种子；
- 场景参数；
- 算法参数；
- 请求步数与实际步数。

第一轮跨难度评估只在相同观测和动作维度下进行：

| 训练场景 | 测试场景 |
| --- | --- |
| `easy` | `easy/medium/hard` |
| `medium` | `easy/medium/hard` |
| `hard` | `easy/medium/hard` |

### 9.2 交付物

- 支持场景参数的统一命令行入口；
- 训练场景与测试场景矩阵；
- 每种方法的原始回合结果；
- 跨种子汇总表和配对差异表；
- 学习曲线和难度泛化图；
- 完整 `experiment_config.json`；
- 模型、TensorBoard 日志和运行命令留档。

### 9.3 验收标准

- 规则基线和学习方法使用相同配对测试场景；
- 同一输出目录不会混淆训练场景和测试场景；
- 结果表可追溯到唯一场景配置、算法配置和随机种子；
- 训练和评估维度不兼容时给出明确错误；
- 至少完成一次包含 2 个场景、2 种方法和 2 个种子的 smoke run；
- smoke run 生成结果表、配置、曲线和配对统计；
- 原默认正式基准命令仍可执行。

## 10. 任务六：运行筛选实验

### 10.1 实验目的

筛选实验不是形成最终论文结果，而是定位算法分水岭和失效模式。

推荐方法：

```text
greedy_damage
hungarian_damage
maskable_ppo
ppo 仅作为动作掩码消融
```

推荐初始规模：

```text
训练步数：20,000 至 30,000
训练种子：3 个
曲线检查点：每 5,000 步
最终评估：每个种子至少 50 个配对回合
```

### 10.2 分析内容

- 各方法随难度变化的性能下降速度；
- 资源压力、时间压力和不确定性压力的独立影响；
- Maskable PPO 是否表现出资源保留优势；
- Hungarian 是否只在即时收益上占优；
- MLP 策略是否在关系复杂度提高后明显失效；
- 奖励、损伤、弹药和高威胁突防之间的权衡。

### 10.3 交付物

- 筛选实验配置；
- 原始数据和汇总表；
- 难度性能曲线；
- 失败案例与典型回合分析；
- 一份诊断报告；
- 正式实验场景和方法选择结论。

### 10.4 验收标准

- 至少完成 `easy/medium/hard` 三个场景的统一评估；
- 每个比较使用相同配对场景；
- 能指出至少一种方法在某类压力下的明确失效模式；
- 能区分“算法能力不足”和“场景本身不可完成”；
- 能解释结果差异来自资源保留、即时匹配、动作合法性或表示能力中的哪一类因素；
- 如果所有方法始终接近，或所有方法同时完全失败，应先重新校准场景；
- 未找到可解释算法分水岭前，不进入正式 GNN 对比实验。

### 10.5 完成记录

任务六已按推荐协议完成：

```text
训练场景：medium
测试场景：easy/medium/hard + 5 个单因素压力场景
方法：greedy_damage/hungarian_damage/ppo/maskable_ppo
训练规模：20,000 请求步，3 个种子
最终评估：50 个配对回合/场景/种子
原始评估回合：4,800
```

筛选实验定位到：普通 PPO 的 no-op 塌缩、Maskable PPO 的跨种子低交战陷阱、`time_pressure` 和 `heterogeneity_pressure` 的稳定方法差异，以及 `hard` 的场景可行性边界。完整数据、置信区间和典型回合见[任务六诊断报告](../experiments/air_defense_v1_task6_screening.md)。

## 11. 任务七：运行关键场景正式实验

### 11.1 进入条件

只有筛选实验满足以下条件才进入正式实验：

- 场景难度排序成立；
- Hungarian 基线正确并通过测试；
- 至少找到一个有区分度的关键场景；
- 关键指标和失败模式已经明确；
- 训练预算足以进入稳定阶段。

### 11.2 推荐协议

```text
训练步数：100,000 或根据学习曲线重新确定
训练种子：5 个
最终评估：100 回合 / 场景块，共 500 回合 / 方法
统计方法：跨运行配对 Student-t 95% CI
```

正式实验不必对全部筛选配置重复运行，只选择最能回答研究问题的场景。

### 11.3 验收标准

- 完整运行没有缺失种子、模型或配置；
- 主要指标报告跨种子均值、标准差和 95% CI；
- 方法间差异采用配对场景分析；
- 结果同时报告任务性能、资源效率和决策耗时；
- 结论严格区分均值趋势与置信区间支持的稳定差异；
- 正式报告明确回答强化学习相对 greedy/Hungarian 的优势与不足；
- 所有图表和表格可由原始数据重新生成。

### 11.4 完成记录

任务七已按正式协议完成：

```text
训练场景：medium
测试场景：medium/time_pressure/heterogeneity_pressure
方法：greedy_damage/hungarian_damage/maskable_ppo
训练规模：100,000 请求步，5 个种子
```

正式结果表明：Maskable PPO 在三个核心场景的奖励和损伤上未与规则基线形成显著差异；在 `medium` 中拦截率更高，在 `time_pressure` 中稳定减少弹药和资源成本；但在 `heterogeneity_pressure` 中高威胁突防率更高，并在全部场景中存在稳定的联合分配冲突。完整结论见[任务七正式实验报告](../experiments/air_defense_v1_task7_formal_100k.md)。

## 12. 图结构算法的进入条件

图结构方法不应因为“看起来适合任务”就直接加入。进入 Graph Maskable PPO 阶段前，至少满足：

1. 难度与泛化实验表明平坦 MLP 在关系复杂度或场景变化下存在瓶颈；
2. 强规则或优化基线已经建立；
3. 动作掩码保持不变，可以隔离表示结构的影响；
4. 已确定图节点、关系边和主评价指标；
5. 已选择具有区分度的训练与测试场景。

推荐算法对照：

```text
MLP Maskable PPO
vs.
Graph Maskable PPO
```

必须保持相同：

- 环境和奖励；
- 动作掩码；
- 训练步数；
- 随机种子；
- 评估场景；
- PPO 超参数，除图编码器必要参数外。

图结构阶段的最低验收标准：

- 在 hard 或未见参数分布上，主要任务指标相对 MLP 有一致改善；
- 至少一个预先指定的主要指标，其配对差异 95% CI 不跨 0；
- 或者在损伤与资源消耗之间形成明确的 Pareto 改善；
- 完成图编码器、关系边和动作掩码的消融实验；
- 参数量和决策耗时被报告；
- 如果没有稳定改善，应如实结论为“图表示未解决当前瓶颈”，而不是继续增加模型复杂度。

## 13. 暂缓任务

本阶段暂不实施：

- PettingZoo 多智能体环境；
- MAPPO、HAPPO、QMIX 等多智能体算法；
- 局部观测和通信延迟；
- 雷达探测、跟踪置信度和 AoI；
- 电子干扰和软杀伤资源；
- 攻防双方同时学习；
- 高保真雷达、弹道和毁伤模型；
- 目标数量变化下的跨规模策略泛化。

这些内容应在集中式图结构策略和环境压力测试完成后再选择性加入。

## 15. 建议近期工作批次

### 第一批：场景与强基线

```text
1. 冻结默认配置；
2. 实现场景注册表；
3. 增加 easy/medium/hard；
4. 增加单因素压力场景；
5. 实现 Hungarian 基线；
6. 完成对应单元测试。
```

### 第二批：指标与实验框架

```text
1. 增加诊断指标；
2. 扩展统一 benchmark；
3. 增加训练/测试场景参数；
4. 运行多场景 smoke test；
5. 验证结果留档和配对统计。
```

### 第三批：诊断与正式实验

```text
1. 运行 3 seeds 筛选实验；
2. 校准难度配置；
3. 分析典型失败案例；
4. 选择关键场景；
5. 运行 5 seeds 正式实验；
6. 编写阶段实验报告。
```

### 第四批：算法创新

```text
1. 明确图节点和关系边；
2. 实现 Graph Maskable PPO；
3. 与 MLP Maskable PPO 公平比较；
4. 完成结构与约束消融；
5. 决定是否进入多智能体扩展。
```

## 16. 阶段完成定义

本阶段不以“新增了多少算法或环境功能”为完成标准，而以是否形成下面的研究闭环为准：

```text
场景压力可控
    +
强基线可信
    +
失败条件明确
    +
实验统计完整
    +
创新方向由证据驱动
```

当项目能够明确指出“现有方法在哪里失败、为什么失败、拟议算法具体解决哪一项失败”时，本阶段才算完成，并具备进入核心算法创新的条件。
