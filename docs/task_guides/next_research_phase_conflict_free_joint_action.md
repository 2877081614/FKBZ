# 下一研究阶段：无冲突联合动作机制

更新时间：2026-07-17  
适用环境：`AirDefenseResourceAssignmentEnv v1.0`  
阶段编号：任务八  
阶段状态：工程实现与 30k 筛选完成，100k 正式实验暂缓  
阶段主题：联合动作约束、资源效率保持与异质目标优先级验证

## 1. 阶段背景

前七项任务已经完成环境冻结、场景分层、强规则基线、诊断指标、统一实验、筛选实验和 100k × 5 种子正式实验。

任务七得到以下正式证据：

- Maskable PPO 在 `medium/time_pressure/heterogeneity_pressure` 的奖励和损伤上未与 Greedy/Hungarian 形成显著差异；
- `medium` 中 Maskable PPO 的拦截率显著更高；
- `time_pressure` 中 Maskable PPO 平均少使用约 2.54 发弹药，资源成本显著降低；
- `heterogeneity_pressure` 中 Maskable PPO 的高威胁突防率显著高约 4.4 个百分点；
- Maskable PPO 在三个场景中均存在约 1.6%–2.5% 的联合分配冲突和过度分配；
- Greedy 和 Hungarian 通过一对一分配保证冲突率为 0。

这说明当前主要问题已经从“单个动作是否合法”转变为：

```text
多个防御资源分别选择合法动作后，联合动作是否仍满足一对一协调约束？
```

## 2. 核心研究问题

本阶段回答：

> 在保持环境、奖励、状态表示和 PPO 超参数不变的条件下，显式构造无冲突联合动作空间，能否消除重复分配，降低异质性场景中的高威胁突防，同时保留时间压力下的资源效率优势？

需要区分两个潜在瓶颈：

```text
动作协调瓶颈：多个资源独立选择时产生重复目标分配
表示能力瓶颈：即使联合动作无冲突，策略仍不能正确理解资源-目标关系
```

任务八首先隔离动作协调瓶颈。只有消除冲突后异质性问题仍然存在，才进入 GNN 表示研究。

### 3.2 本阶段保持不变

- `AirDefenseResourceAssignmentEnv v1.0` 的状态转移；
- 观测空间和特征含义；
- 奖励函数及其权重；
- 目标生成、命中概率和毁伤模型；
- MLP 网络结构；
- PPO 核心超参数；
- 任务七的训练和评估场景；
- 配对评估种子协议和指标定义。

### 3.3 本阶段暂缓

- GNN、注意力编码器或 Transformer；
- MAPPO、HAPPO 等多智能体算法；
- 奖励重构或额外冲突惩罚；
- 目标数和资源数变化；
- AirDefense v1.5 环境升级；
- 同时修改状态表示与动作机制。

不得通过环境执行前的“动作修复”把冲突动作静默替换为其他动作。这样会导致 PPO 计算概率的动作与环境实际执行动作不一致，破坏策略梯度语义。

## 4. 推荐技术方案

### 4.1 原始动作空间

当前场景包含 3 个防御单元和 5 个目标。每个单元可以选择 5 个目标之一或 no-op：

```text
MultiDiscrete([6, 6, 6])
联合动作数量 = 6^3 = 216
```

原始动作掩码保证每个单元选择的动作分别合法，但不能阻止两个或三个单元同时选择同一目标。

### 4.2 无冲突动作集合

只保留所有非 no-op 目标互不重复的联合动作。设实际参与交战的单元数量为 `k`，动作总数为：

```text
sum(C(3, k) * P(5, k), k=0..3)
= 1 + 15 + 60 + 60
= 136
```

包装后的动作空间定义为：

```text
Discrete(136)
```

每个离散动作索引唯一映射到一个长度为 3 的原始联合动作，例如：

```text
encoded_action = 17
decoded_action = [target_2, no-op, target_4]
```

### 4.3 推荐模块

建议新增：

```text
rein_learning/envs/air_defense_v1/wrappers/
    __init__.py
    conflict_free_joint_action.py
```

主要对象：

```text
ConflictFreeJointActionCodec
ConflictFreeJointActionWrapper
```

职责划分：

| 模块         | 职责                                      |
| ---------- | --------------------------------------- |
| Codec      | 确定性生成 136 个动作、编码、解码和空间签名                |
| Wrapper    | 暴露 `Discrete(136)`、生成动态掩码、解码后调用原环境      |
| Trainer    | 使用包装后的环境训练和评估 Maskable PPO              |
| Experiment | 注册 `conflict_free_maskable_ppo` 并完成配对比较 |

### 4.4 动态动作掩码

包装器首先读取基础环境的逐资源动作掩码。对于候选联合动作 `a=(a_1,a_2,a_3)`：

```text
joint_mask(a) = all(base_mask(unit_i, a_i) for i=1..3)
```

候选集合已经在静态编码阶段排除了重复目标，因此运行时只需判断各资源动作是否满足弹药、冷却、射程和目标存活约束。

动态掩码必须满足：

- 返回 `bool[136]`；
- 全 no-op 动作始终可用；
- 任何 mask=True 的动作解码后均可由基础环境接受；
- 相同状态下重复调用返回相同结果；
- 不改变基础环境的观测、奖励和终止语义。

### 任务八六：运行 30k × 3 种子机制筛选

正式筛选协议：

```text
训练场景：medium

方法：greedy_damage/hungarian_damage/
      maskable_ppo/conflict_free_maskable_ppo

训练步数：30,000
最终评估：50 个配对回合/场景/种子
曲线检查点：10,000/20,000/30,000
```

主要比较统一定义为：

```text
conflict_free_maskable_ppo - maskable_ppo
```

工程筛选门槛：

| 指标                              | 进入正式实验的门槛                  |
| ------------------------------- | -------------------------- |
| 非法动作率                           | 必须为 0                      |
| 冲突率                             | 必须为 0                      |
| 过度分配率                           | 必须为 0                      |
| `medium` 平均奖励                   | 相对原方法下降不超过 5               |
| `medium` 平均损伤                   | 相对原方法增加不超过 0.10            |
| `time_pressure` 资源成本            | 相对原方法增加不超过 0.50            |
| `time_pressure` 平均奖励            | 相对原方法下降不超过 5               |
| `heterogeneity_pressure` 高威胁突防率 | 平均下降至少 0.02，且至少 2/3 种子方向一致 |
| `heterogeneity_pressure` 平均损伤   | 相对原方法增加不超过 0.10            |

这些是进入正式实验的工程筛选阈值，不是论文显著性结论。

筛选验收标准：

- 4 种方法、3 个场景和3个种子完整运行；
- 原始回合可重聚合得到全部汇总指标；
- 主要比较使用相同配对场景；
- 至少满足全部结构性门槛；
- 性能门槛未满足时不直接扩大到 100k × 5 种子；

## 6. 结果解释与决策树

```text
冲突是否降为 0？
├─ 否：动作枚举、动态掩码或指标实现存在错误，返回工程修复
└─ 是
   ├─ 高威胁突防下降且资源效率保持
   │  └─ 联合动作约束构成有效创新，进入正式消融与论文方法整理
   ├─ 高威胁突防不变，但总体性能不退化
   │  └─ 动作瓶颈已隔离，异质关系表示可能是下一瓶颈，可论证进入 GNN
   └─ 奖励或损伤明显退化
      └─ 检查离散联合空间探索，再考虑顺序/自回归动作策略，不进入 GNN
```
