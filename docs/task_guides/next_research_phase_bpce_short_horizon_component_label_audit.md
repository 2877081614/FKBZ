
## 2. 证据基线

阶段 A 已经得到以下可冻结结论：

1. A/B 总体符号一致率为 `0.901`，可靠符号反转为 `0/24`，现有证据不支持把 masked-argmax target 视为主要方向错误来源；
2. B/C 总体符号一致率为 `0.778`，低于 `0.80` 门槛，deterministic continuation 不能稳定代表冻结随机策略的条件期望；
3. 标签 C 只有 `25/72` 个可靠上下文，低于 `48/72` 门槛；
4. `time_pressure` 的可靠正/负标签为 `10/0`；
5. `heterogeneity_pressure` 的可靠正/负标签为 `14/1`；
6. 资源槽没有产生可靠负标签，因此当前问题不是损失函数没有平衡已有负类，而是缺少可供平衡的可靠停止证据；
7. Actor 最大参数差为 `0.0`，失败可以归因于标签机制，而不是训练过程混入。

因此，下一步应修正的是**标签所表达的决策命题**，而不是标签进入 PPO 的剂量。

## 3. 补充探索性筛查

对现有
[`repeat_deltas.csv`](../../results/air_defense_v1/bpce_label_semantics_audit/repeat_deltas.csv)
进行只读探索性筛查。该筛查不是预注册实验，不能用于通过门控，只用于判断下一实验的必要性。

使用现有容差：

```text
zone damage 最小有意义改善：0.05
high-threat leakage 最小有意义改善：0.10
```

将一个上下文暂时视为“潜在停止候选”的条件为：

```text
zone damage 改善的95%上界不超过0.05
且 high-threat leakage 改善的95%上界不超过0.10
且 resource cost 增量的95%下界大于0
```

探索性结果为：

| 场景/槽位                             | 上下文数 | 潜在停止候选 |
| --------------------------------- | ----:| ------:|
| time pressure / safety            | 18   | 1      |
| time pressure / resource          | 18   | 0      |
| heterogeneity pressure / safety   | 18   | 2      |
| heterogeneity pressure / resource | 18   | 10     |
| 合计                                | 72   | 13     |

这13个候选在场景和种子间分布不均，不能满足跨种子双向覆盖。该结果提示：

1. 仅把完整回合总回报拆成完整回合分量，大概率仍不足以修复标签；
2. `time_pressure` 中的停止证据尤其容易被完整回合后续收益或方差淹没；
3. 必须验证与当前交战对象直接相关的短视窗安全后果；
4. 现有结果只保存完整回合分量，没有逐步事件窗分量，因此需要重新运行冻结 Actor 的分支评估，不能只做离线重标。

## 4. Problem–Method–Insight

| 层次      | 本阶段表述                                                                                                   |
| ------- | ------------------------------------------------------------------------------------------------------- |
| Problem | 完整回合标量回报把当前交战的局部安全收益、资源消耗和随机后续策略混合在一起，使“没有必要交战”必须表现为负的完整回报，导致资源停止方向在当前两类场景中不可辨识。                        |
| Method  | 保留 BPCE 的成对反事实探测、合法目标精确边缘化和随机策略延续，仅将标签读出改为目标相关事件窗内的安全收益与资源成本双分量估计，并使用 `ENGAGE / STOP / AMBIGUOUS` 三态门控。 |
| Insight | 资源停止监督不应等同于“交战产生负总回报”；它更适合被检验为“能够排除交战达到最小有意义安全收益，同时交战产生确定资源代价”的约束可行性命题。                                 |

该表述目前只是待验证假设。只有阶段 A2 通过后，才能将其提升为候选算法设计依据。

## 7. 冻结反事实定义

本阶段只使用原标签 C 的动作语义：

```text
合法目标精确概率边缘化
+ 冻结策略随机延续
+ engage/no-op 共享环境随机带
+ engage/no-op 共享策略 uniform tape
```

对上下文 `i` 的每个合法目标 `j`，先分别得到：

```text
engage(i, j)
noop(i)
```

再按冻结策略在合法目标集合上的条件概率 `p(j | engage, i)` 进行边缘化。

本阶段不再比较 argmax target 或 deterministic continuation，因为阶段 A 已经完成对应归因。

## 8. 目标相关事件窗

### 8.1 主分析视窗

对每个上下文—合法目标对 `(i,j)`，从分支动作执行时刻开始，以快照中该目标的
`time_to_impact` 冻结一个目标相关事件窗：

```text
H(i,j)
= min(
    remaining_episode_steps,
    ceil(time_to_impact(i,j)) + 1
  )
```

两个分支必须使用完全相同的 `H(i,j)`，不得因为某个目标在 engage 分支提前被摧毁而提前停止统计。

该视窗的目的不是估计完整策略价值，而是覆盖“若当前不干预，该目标预计到达保护区”的直接决策后果。

### 8.2 完整回合对照

同一次 rollout 继续保留完整回合分量，作为诊断对照：

- 短视窗是主分析；
- 完整回合是机制解释；
- 不得根据两者结果事后选择更有利的标签定义；
- 不要求两种视窗符号高度一致，因为本阶段正是在检验完整回合混合是否改变局部决策语义。

## 9. 分量定义

统一使用“engage 减 no-op”的原始差值：

```text
Delta_D = zone_damage_engage - zone_damage_noop
Delta_L = high_threat_leaks_engage - high_threat_leaks_noop
Delta_C = resource_cost_engage - resource_cost_noop
```

解释为：

- `Delta_D < 0`：交战减少区域毁伤；
- `Delta_L < 0`：交战减少高威胁泄漏；
- `Delta_C > 0`：交战增加资源成本。

对每个合法目标分别计算目标相关事件窗分量，再按冻结目标概率精确边缘化，最后在32次配对重复上计算均值、标准误和95%置信区间。

主分析等效阈值冻结为：

```text
epsilon_D = 0.05
epsilon_L = 0.10
```

这两个阈值沿用阶段 A 已冻结的安全分量容差，避免根据 A2 结果重新选择。资源成本只检验是否严格大于0，不另设事后阈值。

## 10. 三态标签定义

### 10.1 ENGAGE

当至少一个安全分量存在超过最小有意义效应的可靠改善，且另一安全分量没有超过既有容差的可靠恶化时，定义为 `ENGAGE`。

建议冻结判据：

```text
(
  upper95(Delta_D) < -epsilon_D
  and upper95(Delta_L) <= epsilon_L
)
or
(
  upper95(Delta_L) < -epsilon_L
  and upper95(Delta_D) <= epsilon_D
)
```

### 10.2 STOP

当两个安全分量均没有证据表明交战达到最小有意义改善，同时交战确定增加资源成本时，定义为 `STOP`：

```text
lower95(Delta_D) >= -epsilon_D
and lower95(Delta_L) >= -epsilon_L
and lower95(Delta_C) > 0
```

这是单侧最小收益排除与资源约束的联合判据：置信区间必须排除超过阈值的安全改善，不能把“没有拒绝零假设”误写成“证明没有安全收益”。

### 10.3 AMBIGUOUS

其余上下文均为 `AMBIGUOUS`，包括：

- 安全分量置信区间过宽；
- 一个分量改善、另一个分量可靠恶化；
- 安全收益低于 ENGAGE 门槛，但尚不能进入安全等效区间；
- 资源成本方向不确定。

`AMBIGUOUS` 不得被强行分配为 ENGAGE 或 STOP，也不得进入后续辅助损失。

## 12. 决策规则

### 12.1 阶段 A2 全部门控通过

允许冻结短视窗双分量三态标签，并进入阶段 B 辅助剂量审计。

阶段 B 必须相应遵守：

- 只使用 ENGAGE 和 STOP；
- AMBIGUOUS 严格掩码；
- 任一 minibatch 缺少一个方向时，双类辅助项退化为0；
- 不得把短视窗安全分量重新加权成未经审计的单一总回报标签。

### 12.2 总体功效通过，但任一场景或种子缺少一个方向

阶段 A2 仍判定失败，阶段 B/C 继续冻结。

此时只允许开展只读原因归因，判断失败来自：

- 当前状态分布中缺少真实停止决策；
- 原资源槽选点没有捕获停止状态；
- 环境奖励和动力学使当前交战在该场景内几乎总有安全收益；
- 事件窗仍不足以隔离当前动作后果。

原因归因不得被解释为已经获得可训练标签。若后续另立选点可观测性任务，必须单独预注册，不能追加到本次正式结果中。

### 12.3 短视窗仍不能形成跨种子双向覆盖

暂停 BPCE 在线辅助主线，不增加分支重复或训练预算。

保留成果：

- strict joint PPO fallback；
- 成对反事实分支与共同随机数基础设施；
- target argmax 不是主要方向错误来源的证据；
- deterministic continuation 在低功效上下文中失稳的证据；
- 完整回合与短视窗 engagement 标签的可辨识性边界；
- 三态约束标签的失败或适用范围。

论文叙事应转为受控失败机制与局部信用可辨识性结论，而不是继续宣称 BPCE 已经解决 all-noop 或资源过度交战。

## 15. 审稿压力点与预防措施

| 风险          | 可能质疑                       | 预防措施                                                  |
| ----------- | -------------------------- | ----------------------------------------------------- |
| 视窗事后选择      | 是否尝试了多个视窗并只报告最有利结果？        | 主视窗由目标快照的 time-to-impact 决定，公式在运行前冻结；完整回合只作对照。        |

## 19. 阶段 A2 正式结论

正式审计完成72个原上下文和2304条配对重复，上下文身份匹配72/72，目标

低于48/72门槛。完整回合对照为14/13/45，短视窗只增加4个可操作标签。
