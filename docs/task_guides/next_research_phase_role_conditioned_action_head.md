# 下一研究阶段：角色条件化关系动作头与顺序鲁棒性

更新时间：2026-07-17  
适用环境：`AirDefenseResourceAssignmentEnv v1.0`  
阶段编号：任务十一  
阶段状态：已完成（未触发条件性 100k 确认实验）  
阶段主题：资源-目标关系评分、单元塌缩抑制与固定顺序鲁棒性

## 1. 阶段背景

任务十已经完成逐决策诊断和三个循环顺序的 30k × 3 种子消融，得到以下证据：

- 三种顺序的非法动作、联合分配冲突和过度分配均严格为 0；
- `order_012` 中第二枚导弹的异质场景分配率仅为 0.52%，可行动时 no-op 比例为 99.44%；
- 任务九冻结模型种子 2 中，第二枚导弹完全不分配，激光分配率仅为 0.28%；
- 该种子 80% 的高威胁泄漏属于“存在合法机会但未分配”；
- `order_201` 让两枚导弹均保持约 6.4% 的分配率；
- `order_201` 将异质场景高威胁泄漏率降低 0.021729，且 2/3 种子同向；
- 但 `order_201` 在时间压力场景的资源成本相对 `order_012` 增加 4.253，未通过 +0.50 门槛；
- 没有固定顺序同时满足高威胁保护和资源效率，因此未运行 100k 确认实验。

这些结果说明固定顺序确实改变资源参与模式，但单纯换序只能把低交战偏置从一个单元转移到另一个单元，或者通过更积极开火换取较低泄漏。当前最值得检验的解释是：

> 现有 Actor 最终输出为每个动作位置提供独立 logits，缺少共享的资源角色与目标关系归纳偏置，因此某些单元动作头容易在训练种子和固定顺序共同作用下塌缩。

任务十一先实现轻量角色条件化关系动作头，不直接进入 GNN。

## 2. 核心研究问题

本阶段回答：

1. 共享的资源-目标评分器能否防止某个单元长期退化为 no-op？
2. 显式输入资源类型、射程、命中率、成本和目标属性后，能否提升异质目标匹配质量？
3. 在不增加资源消耗的条件下，能否降低高威胁目标的 `unassigned` 泄漏？
4. 使用同一关系动作头时，三个固定生成顺序的性能差异是否明显缩小？
5. 剩余问题是否已经足以支持进入更复杂的图关系编码器研究？

## 3. 研究假设

### H1：独立动作位置头导致单元塌缩

当前展平 MLP 最终输出的不同动作段具有独立参数。共享单元-目标评分函数后，相同的决策规则会应用到所有防御单元，单个位置不应轻易形成长期 no-op 塌缩。

### H2：角色条件化提高匹配质量

将资源类型、剩余弹药、冷却、射程、命中率和成本与目标威胁、载荷、突防时间及相对几何关系共同输入评分器，应提高 `matching_efficiency` 和高威胁分配率。

### H3：共享评分降低顺序敏感性

如果动作头学习的是资源-目标关系而不是固定输出位置偏好，则在 `012 / 120 / 201` 三个生成顺序下，性能和资源成本的均值跨度应小于任务十。

### H4：改进不能依靠无约束开火

高威胁泄漏下降必须同时守住资源成本、奖励和毁伤门槛。仅将 `unassigned` 转化为大量 `attempted_miss` 不构成任务通过。

## 4. 阶段边界

### 4.1 允许修改

- Actor 的观察解析和动作 logits 生成方式；
- 防御单元、目标、全局状态的模型侧结构化切片；
- 共享资源编码器、共享目标编码器和共享成对评分 MLP；
- no-op 评分头；
- 自回归条件分布与角色条件动作头的接口；
- 模型签名、方法注册、参数量统计和实验 schema；
- 单元塌缩、顺序跨度和关系匹配诊断；
- 对任务十冻结结果的只读引用。

### 4.2 必须保持不变

- AirDefense v1.0 的状态值、观察顺序、转移、命中和毁伤机制；
- 环境奖励及所有奖励权重；
- 三个核心场景配置和高威胁阈值 0.8；
- `MultiDiscrete([6,6,6])` 环境动作语义；
- 自回归已选目标条件掩码；
- 一个联合动作只推进一个环境时间步；
- PPO 的学习率、rollout、batch、折扣和优化轮数；
- Critic 的输入、结构和训练方式；
- 任务十评估种子公式和决策指标定义。

### 4.3 暂缓内容

- GNN、图注意力、Transformer 或消息传递；
- 学习式动态排序网络；
- 奖励塑形和资源成本权重调整；
- AirDefense v1.5 或多智能体环境；
- 目标数量、资源数量或场景难度扩展；
- 反向选择结果最好的单一固定顺序作为“新算法”；
- 未通过筛选就运行 100k 正式实验。

## 5. 候选模型设计

### 5.1 结构化观察解析

保持环境输出的一维向量不变，仅在模型内部根据 AirDefense v1.0 冻结布局恢复：

```text
zones:   [num_zones, zone_feature_dim]
targets: [num_targets, target_feature_dim]
units:   [num_units, unit_feature_dim]
global:  [global_feature_dim]
```

解析器不能复制一套容易漂移的魔法索引。应由一个可测试的布局签名统一提供切片范围，并校验观察总维度、单元数和目标数。

环境观察值和顺序不变，因此该改动属于模型结构，不属于环境版本升级。

### 5.2 共享实体编码

对所有防御单元共享编码器 `f_u`，对所有目标共享编码器 `f_t`：

```text
u_i = f_u(unit_features_i)
t_j = f_t(target_features_j)
g   = f_g(zone_features, global_features)
```

资源类型必须来自现有 unit feature，不能使用只对单元索引 0/1/2 生效的可学习位置 embedding。允许加入统一的资源类型 embedding，但必须按 `resource_type` 查表并跨位置共享。

### 5.3 资源-目标关系评分

每个单元-目标动作由同一个成对评分器生成：

```text
r_ij = concat(
    u_i,
    t_j,
    g,
    relative_position_ij,
    distance_ij,
    range_margin_ij,
    estimated_hit_probability_ij,
    resource_cost_i
)

logit(i,j) = f_pair(r_ij)
```

若命中概率或距离可以从现有观察确定，则在模型内使用结构化张量计算；不能调用环境内部状态形成训练时不可复现的旁路信息。

动作合法性仍由环境基础掩码和自回归前缀掩码控制，评分器不能替代 action mask。

### 5.4 no-op 评分

每个单元的 no-op logit 使用共享函数：

```text
noop_logit_i = f_noop(u_i, g, pooled_legal_target_context_i)
```

`pooled_legal_target_context_i` 只能由当前观察和基础合法掩码构造。所有单元共享 `f_noop`，防止某一固定动作段形成独立 no-op 偏置。

### 5.5 自回归顺序

主方法保持规范顺序 `012`，用于与任务九和任务十直接比较。`120` 和 `201` 只作为同结构的顺序鲁棒性诊断：

```text
role_conditioned_ar_ppo_order_012  # 主方法
role_conditioned_ar_ppo_order_120  # 诊断方法
role_conditioned_ar_ppo_order_201  # 诊断方法
```

首轮不实现随机顺序和动态排序。只有共享关系头明显改善性能但仍存在固定顺序跨度时，才进入后续“均衡循环顺序”机制。

### 5.6 参数量控制

为避免把改进归因于单纯增大网络容量：

- Actor 可训练参数量相对任务十 Actor 增减不超过 15%；
- Critic 参数量严格不变；
- 编码维度和 MLP 层数必须写入实验配置；
- 输出 `model_parameter_counts.json`，分别记录 Actor、Critic 和总参数量；
- 若无法满足 ±15%，必须先运行容量匹配的展平 MLP 对照。

## 6. 新增诊断指标

任务十 schema 6 指标继续保留，并新增以下聚合量：

| 指标 | 定义 |
| --- | --- |
| `collapsed_unit` | 单元至少有 100 个可行动决策，且分配率低于 1% |
| `collapsed_unit_count` | 指定方法/场景/种子中的塌缩单元数量 |
| `unit_assignment_cv` | 同类资源单元分配率的变异系数 |
| `order_high_leak_range` | 三个顺序的高威胁泄漏率均值最大值减最小值 |
| `order_resource_cost_range` | 三个顺序的资源成本均值最大值减最小值 |
| `order_damage_range` | 三个顺序的总毁伤均值最大值减最小值 |
| `unassigned_leak_rate` | `unassigned` 数 / 全部高威胁泄漏数 |
| `attempted_miss_leak_rate` | `attempted_miss` 数 / 全部高威胁泄漏数 |

同类资源公平性只比较默认配置中的两个导弹单元，不把激光与导弹直接放入同一变异系数。

工作内容：

### 任务十一·三：实现共享角色条件关系动作头

- 实现共享 unit/target/global 编码器；

- 生成 `[batch, num_units, num_targets + 1]` logits；
- 接入现有自回归掩码分布；
- 统计 Actor/Critic 参数量。

验收标准：

- 相同实体置换后，logits 按相同方式置换；

- 基础掩码和条件掩码行为与任务十一致；

### 任务十一·四：模型保存、加载和统一实验注册

验收标准：

## 8. 30k 筛选门槛

### 8.1 主方法相对任务十 `order_012`

| 指标 | 门槛 |
| --- | --- |
| 非法动作、冲突、过度分配 | 全部严格为 0 |
| Actor 参数量 | 相对基线在 ±15% 内 |
| `medium` 平均奖励 | 下降不超过 5 |
| `medium` 平均毁伤 | 增加不超过 0.10 |
| `time_pressure` 资源成本 | 增加不超过 0.50 |
| `heterogeneity_pressure` 高威胁泄漏率 | 平均下降至少 0.02，至少 2/3 种子同向 |
| `heterogeneity_pressure` 平均毁伤 | 增加不超过 0.10 |
| `heterogeneity_pressure` 塌缩单元 | 三个种子均为 0 |
| 决策耗时 | 平均增加不超过 25% |

### 8.2 相对原始 Maskable PPO 的外部门槛

| 指标 | 门槛 |
| --- | --- |
| `medium` 奖励 | 下降不超过 5 |
| `medium` 毁伤 | 增加不超过 0.10 |
| `time_pressure` 奖励 | 下降不超过 5 |
| `time_pressure` 资源成本 | 增加不超过 0.50 |
| `heterogeneity_pressure` 毁伤 | 增加不超过 0.10 |
| `time_pressure` 成本相对 `Discrete(136)` | 必须更低 |

### 8.3 顺序鲁棒性门槛

三个角色条件顺序的场景均值必须满足：

| 指标 | 门槛 |
| --- | --- |
| `heterogeneity_pressure` 高威胁泄漏率跨度 | 不超过 0.03 |
| `time_pressure` 资源成本跨度 | 不超过 1.00 |
| `heterogeneity_pressure` 总毁伤跨度 | 不超过 0.15 |
| 三顺序塌缩单元 | 每个顺序、每个种子均为 0 |

这些门槛用于判断共享关系头是否真正降低固定顺序敏感性，而不是选出一个碰巧表现更好的排列。

## 9. 决策规则

```text
工程闭环和结构测试是否通过？
├─ 否：修复观察解析、等变性、掩码或模型签名
└─ 是
   ├─ 主方法通过性能、资源、塌缩和顺序鲁棒性全部门槛
   │  └─ 使用独立种子运行 100k 确认实验
   ├─ 关系头改善高威胁泄漏和单元参与，但顺序跨度仍超标
   │  └─ 下一步研究可回放的均衡循环顺序；继续暂缓 GNN
   ├─ 关系头降低顺序跨度，但高威胁泄漏与资源成本仍不能兼顾
   │  └─ 轻量关系表达已受控，可进入 GNN/图注意力方案论证
   ├─ 所有方法主要失败于 attempted_miss 或 never_legal
   │  └─ 先校准环境随机上限和场景可辨识性
   └─ 仍出现种子级低交战塌缩
      └─ 优先诊断 PPO 优化和 no-op 概率，不扩大训练规模
```

## 12. 本阶段完成后的研究位置

任务十一是进入图结构方法前的最后一层轻量关系表示对照。它不预设 GNN 一定有效，而是先回答：共享的资源-目标关系评分是否已经足以解决单元塌缩和顺序敏感性。

可能得到三类结论：

```text
结论 A：关系动作头同时降低泄漏、保持资源效率并降低顺序跨度
        -> 运行独立 100k 确认，形成轻量主方法

结论 B：关系动作头改善单元参与，但固定顺序跨度仍明显
        -> 研究均衡循环顺序或可回放动态顺序

结论 C：关系动作头已消除位置塌缩，但复杂资源-目标关系仍无法表达
        -> 具备进入 GNN/图注意力研究的必要证据
```

无论结果属于哪一类，都必须由结构测试、跨种子性能、资源成本、逐决策行为和冻结门槛共同支持。
