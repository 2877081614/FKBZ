# AirDefense v1.0 场景配置与默认基准快照

更新时间：2026-07-17  
实现模块：`rein_learning/envs/air_defense_v1/scenarios.py`

## 1. 文档目的

本文档记录 `AirDefenseResourceAssignmentEnv v1.0` 的冻结默认配置、命名场景、单因素压力配置和第一轮难度校准结果。

场景系统服务于两个目标：

1. 保证 2026-07-14 正式基准使用的默认环境不会因后续研究发生静默漂移；
2. 在不改变观测和动作维度的条件下，建立可解释的任务难度与压力测试。

## 2. 场景接口

可通过统一接口获得配置：

```python
from rein_learning.envs import (
    get_air_defense_v1_scenario,
    get_air_defense_v1_scenario_profile,
    list_air_defense_v1_scenarios,
)

config = get_air_defense_v1_scenario("medium")
profile = get_air_defense_v1_scenario_profile("hard")
names = list_air_defense_v1_scenarios()
```

`default`、`v1_default` 和 `v1-default` 均为 `medium` 的输入别名。实验留档应使用规范名称 `medium`。

所有配置对象及其嵌套实体均为冻结 dataclass，可以被安全复用。

## 4. 固定空间结构

第一轮场景配置全部保持：

```text
保护区域数 = 2
防御单元数 = 3
目标数 = 5
```

因此所有场景具有相同：

- 观测向量维度；
- `MultiDiscrete` 动作维度；
- 动作掩码形状；
- MLP 与 SB3 策略接口。

本阶段不进行目标数量变化下的跨规模泛化。该任务需要 padding、`target_mask` 或图观测后再开展。

## 5. 组合难度配置

### 5.1 参数差异

| 参数 | easy | medium | hard |
| --- | ---: | ---: | ---: |
| missile 弹药 | 4 / 4 | 3 / 3 | 2 / 2 |
| laser 弹药 | 12 | 10 | 7 |
| missile 基础命中率 | 0.93 | 0.88 | 0.80 |
| laser 基础命中率 | 0.75 | 0.68 | 0.58 |
| 目标速度 | `[0.8, 2.4]` | `[1.0, 3.0]` | `[1.8, 3.5]` |
| 目标威胁 | `[0.4, 0.85]` | `[0.5, 1.0]` | `[0.7, 1.1]` |
| 目标载荷 | `[0.5, 1.2]` | `[0.6, 1.5]` | `[0.9, 1.8]` |

除表中字段外，环境配置与 `medium` 保持一致。

### 5.2 设计含义

- `easy`：资源更充足、拦截更可靠、目标压力更低；
- `medium`：冻结的正式基准；
- `hard`：弹药更少、拦截更不可靠、到达更快且损伤潜力更高。

组合场景用于筛选整体难度，不用于单独归因某一个环境因素。

## 6. 单因素压力配置

| 场景名 | 相对 medium 只改变 | 参数变化 |
| --- | --- | --- |
| `time_pressure` | 目标速度 | `[1.0, 3.0] → [2.0, 3.5]` |
| `resource_pressure` | 防御单元弹药 | `3/3/10 → 2/2/6` |
| `intercept_uncertainty` | 基础命中率 | `0.88/0.88/0.68 → 0.72/0.72/0.52` |
| `damage_pressure` | 目标威胁与载荷 | threat `[0.8, 1.2]`，payload `[1.0, 1.8]` |
| `heterogeneity_pressure` | 单元射程、命中率和成本差异 | 扩大三类资源能力与成本差距 |

`heterogeneity_pressure` 的单元参数：

| 单元 | 射程 | 基础命中率 | 成本 |
| --- | ---: | ---: | ---: |
| D0 missile | 92 | 0.94 | 2.8 |
| D1 missile | 72 | 0.78 | 1.5 |
| D2 laser | 45 | 0.50 | 0.25 |

单因素压力配置的 `changed_fields` 元数据和测试共同约束其改动边界。

## 7. 第一轮难度校准

### 7.1 协议

校准日期：2026-07-17

```text
策略：greedy_damage
场景：easy、medium、hard
回合数：500 / 场景
场景种子：2000 至 2499
配对方式：三个难度使用相同回合种子
```

该校准用于验证场景难度顺序，不作为算法优劣的正式统计结论。

### 7.2 结果

| 场景 | 平均奖励 | 平均损伤 | 拦截率 | 成功率 |
| --- | ---: | ---: | ---: | ---: |
| easy | -15.91 | 0.266 | 0.646 | 0.132 |
| medium | -40.03 | 1.055 | 0.507 | 0.046 |
| hard | -108.11 | 2.822 | 0.334 | 0.002 |

`hard - easy` 配对差异：

| 指标 | 平均差异 | 95% CI |
| --- | ---: | ---: |
| 奖励 | -92.202 | `[-95.105, -89.298]` |
| 损伤 | +2.556 | `[2.492, 2.619]` |
| 拦截率 | -0.313 | `[-0.332, -0.294]` |
| 成功率 | -0.130 | `[-0.160, -0.100]` |

四个指标均呈单调难化趋势，损伤差异置信区间不跨 0，满足第一轮难度校准验收标准。

### 7.3 解释边界

- 以上置信区间以 500 个配对场景为样本，用于场景校准；
- 正式算法对比仍应以独立训练运行作为统计单位；
- `hard` 的成功率接近 0，后续筛选实验应重点检查其是否对学习方法过难；
- 如果所有学习方法在 `hard` 上同时完全失败，应增加位于 `medium` 与 `hard` 之间的配置，而不是直接增加模型复杂度。

## 8. 测试覆盖

场景测试位于：

```text
tests/test_air_defense_v1_scenarios.py
```

当前覆盖：

- `medium` 与原始默认配置完全相等；
- 默认别名解析；
- 场景注册和类型过滤；
- 所有场景的空间维度一致；
- 相同种子生成相同初始状态；
- 所有场景可运行至终止或截断；
- 单因素配置只改变声明字段；
- easy/medium/hard 参数压力方向正确。

验证结果：

```text

场景、环境与导入定向测试：41 passed

```

## 9. 后续使用原则

1. 新实验应显式记录规范场景名称和完整配置；
2. 不直接修改 `medium`，需要变化时新增命名配置；
3. 组合难度用于寻找算法分水岭；
4. 单因素压力配置用于解释性能变化原因；
5. 进入正式 GNN 实验前，应先完成 Hungarian 基线和跨场景统一实验接口。
